## App Shell, Routing & Auth

This is the top-level navigation shell, route table, auth layer, and axios client for the Kaizen Events admin app (React 19, React Router v7 BrowserRouter, shadcn/ui + Tailwind). App.js is a single flat route table of ~66 <Route> declarations wrapping the whole app in ErrorBoundary > AuthProvider > BrowserRouter, with ScrollToTop and a global Sonner <Toaster>. Auth is localStorage-token based (no refresh-token rotation on the client): AuthContext reads token+user from localStorage on mount and exposes login/register/logout plus role helpers (isSuperAdmin, isOrgAdmin, canWrite, canAccessCampaign). ProtectedRoute is a simple presence gate (redirects to /login when no user) and does NOT enforce role or campaign access — those checks live inside AuthContext helpers that individual pages must call. The app has only a top-bar nav (no persistent sidebar on desktop; a slide-in drawer appears on mobile only), styled with hardcoded slate-* Tailwind utilities and brand hex colors. Theming is effectively unwired: next-themes is installed and imported only by the Sonner toaster, Tailwind has darkMode:'class' and a .dark CSS-var block, but no ThemeProvider mounts and nothing ever toggles the .dark class, so the app is permanently light.

### Components
- **App (src/App.js)** — Root component; single flat route table (~66 routes) inside ErrorBoundary > AuthProvider > BrowserRouter > ScrollToTop > Routes; mounts global Sonner Toaster (top-right, richColors, closeButton)
- **ProtectedWithLayout (inline in App.js)** — Convenience wrapper = ProtectedRoute + AppLayout; used by nearly all admin routes. Kiosk route deliberately skips it (ProtectedRoute only, no chrome)
- **ProtectedRoute (src/components/ProtectedRoute.js)** — Auth presence gate: shows a full-screen spinner while loading, redirects to /login when no user, else renders children. No role/campaign enforcement
- **AppLayout (src/components/AppLayout.js)** — Admin shell: sticky white top nav bar with logo, desktop horizontal nav, mobile hamburger + slide-in left drawer, user chip, logout button. Wraps page in <main>
- **AuthContext / AuthProvider (src/context/AuthContext.js)** — Auth state + localStorage token/user persistence; exposes login, register, logout, isSuperAdmin, isOrgAdmin, canWrite, canAccessCampaign, plus user/loading
- **useAuth (src/context/AuthContext.js)** — Hook to consume AuthContext; throws if used outside provider
- **api (src/services/api.js)** — Axios instance (baseURL = REACT_APP_BACKEND_URL + /api). Request interceptor injects Bearer token and X-Instamojo-Session header; response interceptor handles 401 (clear + redirect to /login, except login call) and 403 Instamojo session-expired (redirect to /instamojo)
- **ScrollToTop (src/components/ScrollToTop.js)** — Renders null; on pathname change calls window.scrollTo top (instant). Mounted once inside BrowserRouter before Routes
- **Footer (src/components/Footer.js)** — Shared dark public-site footer (obsidian #171721 bg, gold #CC9E4A accents); Quick Links + Legal columns, social buttons, Host Your Event CTA to /contact-sales. Used by public/marketing pages, not the admin shell
- **KaizenBrandFooter (src/components/KaizenBrandFooter.js)** — Fixed bottom navy branding band shown under public registration forms; external CTA to kaizenevents.live/contact in new tab. Rendered by PublicRegistration, not App shell
- **ErrorBoundary (src/components/ErrorBoundary, referenced)** — Top-level React error boundary wrapping the entire app
- **Toaster (src/components/ui/sonner)** — Global toast host; the ONLY consumer of next-themes useTheme in the shell

### Workflows to preserve exactly
- **Login and session bootstrap:** AuthProvider mounts -> reads localStorage token+user -> sets user (loading gates ProtectedRoute spinner). login() posts /auth/login, stores access_token + user JSON, sets user. Backend progressive-lockout remaining_attempts is surfaced into the error message string — must preserve
- **Protected navigation:** User hits an admin route -> ProtectedWithLayout -> ProtectedRoute checks loading/user -> redirect to /login if absent -> AppLayout chrome renders around page. Preserve the redirect-to-login-with-replace behavior
- **Logout:** AppLayout logout button -> AuthContext.logout() clears token+user and hard-navigates window.location.href='/login' (full reload). Note AppLayout also calls navigate('/login') after, but logout already forces reload
- **401 auto-logout:** Any API 401 (except /auth/login) -> interceptor clears localStorage token+user and hard-redirects to /login. Preserve exception for the login call so Login.js can render its own toast
- **Role-based nav visibility:** AppLayout builds navItems: Dashboard + Events always; Fund Transfers + Control Panel appended only when isSuperAdmin(). Redesign must keep super-admin-only nav gating
- **Instamojo archive session gate:** After /verify-password, frontend stores {token,expires_at} in localStorage instamojoArchiveSession; interceptor attaches X-Instamojo-Session on all /instamojo-archive/* calls except verify-password; on 403 session-expired it clears the session and bounces to /instamojo. Must preserve exactly
- **Scroll reset on route change:** ScrollToTop forces window scroll to top on every pathname change (instant). Preserve to avoid landing mid-page after navigation
- **Kiosk chrome-less mode:** /kiosk/:campaignId uses ProtectedRoute WITHOUT AppLayout so kiosk fills the screen with no admin nav. Redesign must keep kiosk chrome-free

### Backend endpoints used
- `POST /auth/login (AuthContext.login)`
- `POST /auth/register (AuthContext.register)`
- `axios baseURL = REACT_APP_BACKEND_URL + '/api' (all app requests flow through this instance)`
- `Request interceptor: Authorization: Bearer <token>; X-Instamojo-Session on /instamojo-archive/* (except /instamojo-archive/verify-password)`
- `Response interceptor: 401 -> clear session + redirect /login (except /auth/login); 403 'Instamojo (For Accounts\|Archive) session expired' -> clear archive session + redirect /instamojo`

### State management
- React Context (AuthContext) for auth/user state — the only global store in the shell
- localStorage as source of truth for auth: 'token' (JWT access_token) and 'user' (JSON); also 'instamojoArchiveSession' for the archive gate
- Local useState in AppLayout for sidebarOpen (mobile drawer)
- useLocation/useNavigate (react-router) for active-link detection and programmatic navigation
- No Redux/Zustand/React Query at the shell level; each page fetches via the shared axios instance

### Reusable-component opportunities
- Nav item rendering is duplicated between desktop bar and mobile drawer in AppLayout (same navItems.map with near-identical Link markup) — consolidate into one NavLink/NavList component
- Active-link styling (isActive -> bg-primary/10 text-primary vs slate hover) is repeated — extract a shared active-state token/util
- Two footers (Footer, KaizenBrandFooter) plus the admin top bar all re-implement logo + brand color usage — a shared Brand/Logo primitive and a footer variant system would DRY this
- Full-screen loading spinner in ProtectedRoute is bespoke; should become a shared <FullPageLoader> / Skeleton used across route transitions
- User avatar chip (initial circle + name) in AppLayout is a candidate for a reusable Avatar/UserMenu (currently no dropdown — just a static chip + logout button)
- Hardcoded brand hexes scattered across components should be replaced by design-system tokens (semantic Tailwind classes) so a redesign can retheme centrally
- Route table in App.js is a flat ~66-entry list with heavy ProtectedWithLayout repetition — a data-driven route config with nested layout routes (React Router v7 layout routes / <Outlet>) would remove the per-route wrapper boilerplate

## Design Tokens & shadcn UI Kit

This is the design-system baseline for the Kaizen Events admin frontend (CRA + Craco, React 19, Tailwind, shadcn/Radix). It has a SPLIT and CONFLICTING token system: `src/index.css` defines shadcn's HSL CSS variables in `:root` and `.dark`, while `tailwind.config.js` ALSO hardcodes brand hex values for `primary`, `secondary`, and `accent` (plus a `brand.*` palette and a full `slate` ramp) that bypass the CSS vars entirely. The result is that some Tailwind color utilities resolve to branded hex from the config and others resolve to HSL vars from index.css, and the two do not agree. The shadcn primitive kit is essentially complete (~50 files in `src/components/ui/`) and consumes tokens the standard way via `cn()` + Tailwind classes like `bg-primary`, `bg-secondary`, `text-muted-foreground`, `bg-accent`. Fonts (Outfit/Plus Jakarta Sans/JetBrains Mono) load from Google Fonts in index.css. Dark mode and the `--chart-*` vars are defined but effectively DEAD (no `.dark` toggler wired, charts use hardcoded hex instead).

### Workflows to preserve exactly
- **Token consumption via Tailwind utilities:** Every page/component styles through Tailwind classes (bg-primary, text-secondary-foreground, bg-muted, hover:bg-accent-subtle, bg-primary-hover, border-primary, text-primary). A redesign MUST keep these exact class names resolving to sensible colors, or hundreds of call sites across pages/ and components/FormBuilder/ break visually. Extended tokens primary-hover, primary-subtle, accent-subtle, secondary-subtle are actively used (e.g. CampaignModals, FieldRules, FormulaBuilder).
- **Mobile-first sizing contract:** Inputs/buttons/select use h-11 + text-base on touch and sm:h-9 + sm:text-sm on desktop specifically to give >=44px tap targets and suppress iOS Safari focus-zoom (reinforced by the @media max-width:640px font-size:16px rule in index.css). Must be preserved.
- **Toast notifications:** App fires toasts through BOTH Radix toast and sonner. Any theming change must cover both, and sonner's next-themes dependency stays wired even though no theme switcher exists.

### Styling / theming patterns
- Split token system: shadcn HSL vars in index.css :root/.dark AND hardcoded brand hex in tailwind.config.js theme.extend.colors. They are NOT synced.
- CONFLICT: --primary in index.css is HSL '225 74% 16%' (a navy) BUT tailwind primary.DEFAULT is hex #0A1D48 (also navy, close but not identical, ~225 76% 16%); because tailwind's colors.primary is a hex object, `bg-primary` uses the hex and IGNORES --primary entirely. The --primary CSS var is effectively dead for the primary utility.
- CONFLICT/UNBRANDED: --secondary and --accent and --muted in :root are generic grey (0 0% 96.1%), but tailwind overrides colors.secondary -> crimson #9E0E18 and colors.accent -> gold #CC9E4A. So `bg-secondary` = crimson, `bg-accent` = gold, while `bg-muted` (no tailwind override) = grey var. Secondary/accent are branded via config; muted stays grey.
- Dark theme is generic near-black (.dark --background 0 0% 3.9%, --primary flips to near-white 0 0% 98%) NOT navy/brand. It is also effectively unused: no .dark class toggler is wired (only sonner references next-themes), and no `dark:` utilities appear in pages/.
- --chart-1..5 are a rainbow (light: coral/teal/dark-slate/gold/orange; dark: blue/green/orange/purple/pink) and are DEAD CODE: dashboard charts (StatusDonut.js, TrendChart.js) hardcode their own hex (#16a34a/#f59e0b/#dc2626/#94a3b8, bars #c7d2fe, line #6d28d9) and never read the chart vars. Nothing maps --chart-* into Tailwind.
- Purple leftovers from the old #7c3aed brand: tailwind boxShadow.glow = 'rgba(124,58,237,0.3)' and index.css body -webkit-tap-highlight-color = 'rgba(124,58,237,0.15)'; also TrendChart line stroke #6d28d9 (purple).
- borderRadius overridden larger than shadcn default (lg 1rem/md .75rem/sm .5rem) while --radius var stays 0.5rem — another config-vs-var divergence.
- Extensive bespoke marketing CSS layer in index.css (ke-fade/float/shimmer/grid/dots/gold-rule/heading-gradient/conic) using literal brand hex (#0A1D48, #9E0E18, #CC9E4A) rather than tokens — these will not follow any token change.
- Fonts: Outfit (headings, via h1-h6 rule + letter-spacing -0.02em), Plus Jakarta Sans (body), JetBrains Mono (code), loaded from Google Fonts.

## Dashboard & Analytics

The admin Dashboard is a single-page overview at /dashboard (protected, rendered inside AppLayout) driven entirely by src/pages/Dashboard.js plus six presentational widgets in src/components/dashboard/. It loads two things on mount — the campaign list and a lightweight per-registration summary — then computes EVERYTHING client-side: 8 KPI tiles, a combined bar+line trend chart, a payment-status donut, a Top Events ranked list, a Recent Registrations feed, and three mini split cards (gateway revenue, collection method, event status). Three filters (date range 7d/30d/90d/all, event, and payment status) drive a single useMemo view-model, so no analytics endpoint is called on filter change — all aggregation lives in src/utils/dashboardStats.js. The design is a hand-rolled light theme (hardcoded slate/purple hex values, custom fonts font-outfit/font-jakarta) rather than shadcn cards; only the Button component and lucide icons come from the design system. There is a real analytics backend (AnalyticsController / analytics_routes.py) but this dashboard does NOT use it — it recomputes stats in the browser instead, which is a major redesign consideration. Notably there is NO error/empty state at the page level (a failed load only fires a toast and then renders an all-zero dashboard).

- **Conditional field logic:** Field Rules tab → Add Rule → configure When conditions (field/operator/value, all-or-any match) and Then actions (show/hide/require/enable/disable/set_value on a target field) → Save Rules. - **Multi-page forms:** Pages tab → Add Page Break, choose insert-after-field position + title/description → optionally add Page Navigation Rules (from-page → skip_to/go_to/submit → to-page). Total pages = breaks + 1.
- **Theme & brand the form:** Design tab → pick a Form Template (applies theme + sample fields only if form empty), customize 6 theme colors via color pickers, upload banner/header/logo/page+card background images (with logo size slider and show-logo toggle), set submit button text and section heading → Live Preview updates in real-time → 'Preview Form' opens full FormPreview.

- **Build a landing page:** (Super Admin only) Sections tab → add/reorder (up/down arrows, NOT drag despite grip icon)/delete sections, edit via SectionEditor; Theme tab sets 4 colors + registration-button toggle; Templates tab applies one of 47 ready templates → Preview toggles full render → Save writes sections/theme/show_registration_button.

### Workflows to preserve exactly
- **Add/edit payment gateway account:** /payment-accounts → Add Account → pick gateway (locked on edit) → gateway-specific credential fields (masked, blank keeps existing on edit) → mode + Razorpay settlement mode → POST/PUT /payment-accounts. Deleting requires window.confirm.
- **Kaizen-managed fund transfer (full approval chain):** FundManagement or /fund-transfers → Create Transfer (amount defaulted to pending, cannot exceed pending) → POST /fund-transfers (status pending_approval) → Director on /approvals approves/rejects → Super Admin on /fund-transfers clicks Complete → enters txn reference + date + optional email → PUT /fund-transfers/{id}/complete → optional Notify.
- **Change-request approvals:** Bank account / gateway / fund-collection-mode changes are submitted as change-requests (FundManagement modals) → appear in DirectorApprovals with current-vs-new diff → approve/reject via /fund-transfers/change-requests/{id}.
- **Vendor onboarding (admin):** Cashfree KYC or Razorpay Route → Add → fill PAN/bank (with confirm-account match + PAN regex) → Send OTP to admin email → enter 6-digit OTP → POST creates vendor at gateway → refresh status until ACTIVE/activated → optionally Set as Kaizen default with global %.
- **Vendor self-onboarding (public):** Admin generates share-link → vendor opens /vendor-onboarding/{token} → fills form → OTP to vendor email → submit → success/pending screen.
- **Per-campaign vendor splits:** On Edit Campaign, Cashfree or Razorpay split section loads existing/available/default → admin adds rows (percentage/fixed/residual, exactly one residual) → live preview at ₹10,000 → validation (sum %+default < 100) → PUT /campaigns/{id}/vendor-splits.
- **Offline cash verification:** /campaigns/{id}/offline-payments → enter registrant OTP → verify → shows registrant + amount due → enter amount received + notes → confirm → receipt number screen → Verify Next. Also resend OTP / mark no-show from pending list.
- **Instamojo archive access + finance actions:** /instamojo password gate → 1-hour session token in localStorage → list/purposes/payments/reports pages; Show Profit and Paid reports require a second password; deleting a manual payout requires an emailed OTP; 403 anywhere clears session and redirects to gate.
- **Coupon management:** On campaign page, CouponCodes → New/Edit inline form → client validation → POST/PUT/PATCH(status)/DELETE /campaigns/{id}/coupons; edit uses clear_* flags to distinguish 'remove limit' from 'unchanged'.
- **Multi-gateway checkout:** PaymentCheckout POST /payments/create → branch by gateway: Razorpay modal+verify, Instamojo redirect, Cashfree proxy hidden-form POST OR Cashfree JS SDK modal+verify → success/failure callbacks.

### Components
- **ControlPanel** — Admin hub page; builds a controlItems array filtered by role (kiosk_volunteer, can_approve_transfers, isSuperAdmin) and renders Link-wrapped Cards with icon/color/description
- **UserManagement** — User CRUD page: fetches /users + /campaigns, list with role badges + campaign tags, add/edit modal with role select, Director checkbox, campaign-access checkbox list; delete with confirm
- **Integrations** — Integration status dashboard: three Cards (WhatsApp/Email/Sheets) driven by /integrations/status; email test form, sheets service-account email copy, refresh
- **WhatsAppTemplatesManager** — Bulk template editor: trigger picker, common vs custom template editor with body-value/placeholder builder, per-event target table with select-all/search, bulk-apply PUT
- **DKIMRegistration** — Domain + sender manager: domain list with status badges, expandable DNS-records panel, verify/delete; sender grid with add/edit/delete modals; three modals (add domain, add sender, edit sender)
- **ActivityLogs** — Audit viewer: EVENT_TYPE_LABELS map (icon+color+label for ~45 event types), stats cards, collapsible filter panel, IST timestamp formatting, plain HTML table, prev/next pagination
- **Login** — Branded two-panel auth screen using inline-style brand palette; calls useAuth().login, toasts, redirects to /dashboard
- **ForgotPassword** — Two-step (step state) reset flow: request code then confirm; branded layout with Footer, decorative illustration
- **ChangePassword** — Simple form (current/new/confirm) with client validation, posts /auth/change-password, logs out on success
- **ErrorPage (ErrorPage.js)** — Legacy standalone error screen with generated Error ID; reload/home buttons
- **ErrorPages.js module** — Exports reusable ErrorPage (parameterized code/title/message), NotFoundPage, ServerErrorPage, UnauthorizedPage, plus public-facing CampaignArchivedPage, RegistrationClosedPage, RegistrationComingSoon (with live countdown)
- **NotificationSettings** — Per-campaign email settings sub-panel: enable toggle, DKIM sender select, CC/BCC chip inputs, subject template, test-email; WhatsApp block commented out
- **GoogleSheetsSettings** — Per-campaign sheets sub-panel: three render states (not-configured-global, connected, setup-form); create sheet, sync all, restore-deleted (force_full), disable sync
- **OfflinePaymentSettings** — Per-campaign offline-payment sub-panel: enable toggle + deadline date, reads/writes campaign.payment_config; how-it-works OTP info box

### Workflows to preserve exactly
- **Admin login:** Enter email+password on /login -> useAuth().login -> on success toast + navigate('/dashboard'); on failure toast error. Remember-me checkbox present (state only). Forgot Password link -> /forgot-password.
- **Password reset (2-step):** Step 1: enter email -> POST /auth/password-reset-request -> advance to step 2. Step 2: enter 6-digit code + new password + confirm -> POST /auth/password-reset-confirm -> navigate('/login'). Back button returns to step 1. Client validates match before submit.
- **Change password:** Enter current + new + confirm; client checks non-empty, match, and new!=current -> POST /auth/change-password -> toast + logout() -> user must re-login (backend revokes tokens).
- **Create/edit user:** Open Add modal -> fill name/email/password/role; if org_admin must select >=1 campaign (validated); Director checkbox only for Directors editing super_admin role -> POST /auth/register or PUT /users/:id -> refetch. Email disabled on edit; password optional on edit.
- **Delete user:** window.confirm -> DELETE /users/:id -> refetch. Delete hidden for super_admin and Director rows.
- **DKIM domain registration + verify:** Add Domain modal -> POST /dkim/domains -> DNS Records toggle lazily GETs /dkim/domains/:id to self-heal records -> copy records to DNS -> Verify -> POST /dkim/domains/:id/verify -> status badge updates.
- **DKIM sender management:** Add Sender modal (name + domain select + email + default switch) -> POST /dkim/senders. Edit modal updates name + default only (email immutable) via PUT. Delete with confirm.
- **Integration status + email test:** Auto GET /integrations/status; if email configured, enter to_email/to_name -> POST /integrations/email/test. If sheets configured, GET service-email and copy to clipboard. Refresh re-fetches.
- **Bulk WhatsApp template apply:** GET /whatsapp-templates/overview -> pick trigger -> edit common (fixed) or custom (template_name/language/country/body_values/placeholders) -> select target events (default all) -> PUT /whatsapp-templates/bulk-apply -> shows updated/failed counts.
- **Activity log browse:** On mount fetch event-types, stats(7d), users, logs. Optional filter panel (event/resource/user/start/end) -> Apply resets page to 1 and refetches. Prev/next pagination via has_more. Timestamps rendered in Asia/Kolkata IST.
- **Per-campaign notification settings:** GET /notifications/settings/:id + /dkim/senders -> toggle email, choose sender, add CC/BCC chips, edit subject -> Save PUT /notifications/settings/:id (strips interakt_api_key if blank, deletes resend_api_key). Test email POST /notifications/test-email.
- **Per-campaign Google Sheets:** GET /integrations/status + /integrations/sheets/config/:id. Not-configured-globally state; else create sheet (POST create-campaign-sheet), Sync All (force_full=false), Restore Deleted (force_full=true, confirm), Disable Sync (DELETE, confirm).
- **Offline payment settings:** GET /campaigns/:id -> read payment_config; toggle allow_offline_payments + set deadline date -> PUT /campaigns/:id/offline-payment-settings (deadline coerced to T23:59:59Z, null when disabled).

### Styling / theming patterns
- Admin pages: Tailwind utility classes with slate scale (bg-slate-50 page, bg-white cards, text-slate-900/500/400) and shadcn primitives (Button, Card, Input, Label, Switch, Select, Checkbox, Table)
- Semantic theme tokens used inconsistently: primary/primary-hover/primary-foreground, secondary, accent/accent-subtle, shadow-card — mixed with hardcoded Tailwind color scales (bg-blue-100 text-blue-600, amber, green, violet, pink, teal, indigo)
- Custom font utility classes font-outfit (headings) and font-jakarta (body) applied ad hoc, not globally
- Status/role indication via hardcoded color-pair className strings (e.g. bg-green-100 text-green-600) repeated across DKIM, Integrations, ActivityLogs, UserManagement
- Auth pages (Login, ForgotPassword) DO NOT use the token system: they define local const brand colors NAVY/CRIMSON/GOLD/IVORY (#0A1D48/#9E0E18/#CC9E4A/#F7EBE0) and apply them via inline style={{}} objects and arbitrary Tailwind values like bg-[#CC9E4A]/20
- Modals are hand-rolled: fixed inset-0 z-50 + bg-black/50 backdrop-blur-sm overlay wrapping a Card (no Dialog primitive) in UserManagement and DKIMRegistration
- Icons exclusively from lucide-react; loading states use Loader2 animate-spin (or a border-spinner div in UserManagement)
- Error pages use bg-gradient-to-br slate backgrounds and large text-8xl status codes; ErrorPage.js (legacy) differs in style from ErrorPages.js module
- Container widths inconsistent: max-w-7xl (ControlPanel/UserManagement/ActivityLogs), max-w-6xl (DKIM), max-w-5xl (WhatsApp), max-w-4xl (Integrations)

### State management
- Local useState per component; no Redux/Zustand/React Query anywhere in this group
- Global auth via useAuth() from AuthContext: provides user, isSuperAdmin(), login, logout, and reads user.can_approve_transfers (Director) and user.role (kiosk_volunteer/org_admin/super_admin)
- Data fetched imperatively in useEffect via shared axios `api` (src/services/api.js) with Promise.all for parallel loads; refetch-after-mutate pattern (fetchData()) rather than optimistic updates
- Forms held as single object state updated with spread ({...formData, field}); WhatsApp manager uses a Set for selected campaign ids and useMemo for derived rows/filtering
- Toasts via sonner (toast.success/error) for all user feedback; confirmations via native window.confirm / confirm()
- ActivityLogs derives IST timestamps with a module-level Intl.DateTimeFormat and date-fns parseISO/formatDistanceToNow; pagination state (page/hasMore/totalLogs) local
- CampaignSettings.js passes campaignId + campaignName props down to the three settings sub-panels (no context)

### Redesign risk areas
| Severity | Area | Risk |
|---|---|---|
| high | Client-side-only authorization | Every gate (isSuperAdmin, Director, kiosk_volunteer checks) lives in the component and uses useEffect + navigate() redirects. UserManagement enforces 'only Directors can create Directors' and 'org_admin needs >=1 campaign' purely in JS. A redesign must preserve each redirect/guard exactly or expose admin features to the wrong roles; server enforcement is assumed but not visible here. |
| medium | ActivityLogs EVENT_TYPE_LABELS map | A ~45-entry hardcoded map of backend event-type constants to icon/color/label is embedded in the page. It must stay in sync with backend AuditEventType names (LOGIN_SUCCESS, FUND_TRANSFER_*, etc.); redesign risks silently dropping labels for unmapped types (falls back to raw underscore string). |
| medium | Timestamp / timezone logic in ActivityLogs | toDateUtcSafe + IST_FORMATTER hand-handle missing 'Z' suffixes and force Asia/Kolkata display. This is subtle business-correctness logic (audit accuracy) embedded in the UI and easy to break in a rewrite. |
| medium | Two divergent styling systems | Auth pages use inline hardcoded brand hex (NAVY/CRIMSON/GOLD/IVORY) while admin pages use Tailwind theme tokens (primary/slate). A unified design system must reconcile these; the auth palette is not represented in the token set at all. |
| low | Hand-rolled modals | UserManagement and DKIMRegistration implement modals as raw fixed-overlay + Card markup (no Dialog primitive, no focus trap/escape handling). Redesign to a shared Dialog must preserve open/close/submit wiring and the multi-modal state (showAddDomain/showAddSender/editSender). |
| medium | GoogleSheetsSettings multi-state branching | Component returns one of four different UIs (loading, global-not-configured, connected, setup-form) plus force_full sync semantics (Restore Deleted Rows undoes user deletions). This business behavior and its warnings must be preserved verbatim; misrepresenting force_full could cause data-restore surprises. |
| medium | NotificationSettings dead/partial code | Whole WhatsApp block is commented out; references settings.has_resend_key and interakt_api_key though comments say 'Resend no longer used'. Stale flags and conditional test-email enabling (email_sender_id \|\| has_resend_key) make the true enable logic ambiguous for a redesign. |
| low | OfflinePaymentSettings couples to campaign.payment_config | Reads settings out of campaign.payment_config JSON and date-massages deadline (split('T'), append T23:59:59Z, null when disabled). Redesign must keep the exact date coercion or shift OTP-expiry behavior. |
| high | Hardcoded API paths + snake_case payloads | Per project constraint, endpoint paths and field names (snake_case) are contract-locked to the .NET backend. UI refactors must not rename any request field (e.g. can_approve_transfers, campaign_access, force_full, offline_payment_deadline_date) or alter query-param test-email calls. |
| low | Duplicate routing / two ErrorPage exports | Same components mount at both legacy (/users, /dkim, /integrations) and /control-panel/* paths, and there are two distinct ErrorPage implementations (ErrorPage.js vs ErrorPages.js named export). Consolidation risks breaking one of the paths or importing the wrong ErrorPage. |
| low | Cross-feature hardcoded links | NotificationSettings and GoogleSheetsSettings use raw window.location.href='/dkim' and '/integrations' (full reload) instead of router navigation, and Integrations navigates to whatsapp-templates. These couplings must be re-pointed if routes change in redesign. |
